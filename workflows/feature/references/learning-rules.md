# Learning rules

Apply earned learning to the owner that produced the recurring problem. A lesson
is evidence, not a second policy store, and does not delay incident recovery.

| What changed | Owner |
|---|---|
| Product behavior or technical choice | Living brief or its linked decision owner |
| Durable shared architecture rationale | Earned shared ADR, linked by affected Projects |
| Missing workflow step or context | Working contract or routing file |
| Repeated artifact-shape problem | Optional template |
| Durable cross-Project preference | Human-reviewed shared principle |
| Missing class of proof | Testing or review rules |
| Future direction outside accepted work | Roadmap |

Correct the source only when evidence supports recurrence and the human reviews
new lasting guidance. If clear instructions were ignored once, do not duplicate
them. Explain the outcome, limits, and conditions that would invalidate a lesson.
Keep the evidence in the existing PR unless a separate record earns its place.
